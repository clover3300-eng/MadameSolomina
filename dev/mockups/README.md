# Мокапы

Дизайн-макеты, которые не входят в сайт: `public/` их не видит, на деплой не попадают.

## Терминал «Торговли» и режим «Просто»

Восемь экранов: как сейчас · терминал во весь экран · строка терминала крупно ·
тёмная тема · «Просто» · продажа · облигация с НКД · подтверждение сделки.

| файл | что это |
|---|---|
| `trading-mockups.src.html` | **исходник.** Экраны собираются скриптом внутри файла — правим только его |
| `build-mockups.js` | сборщик: выполняет тот скрипт в Node и запекает результат в разметку |
| `trading-mockups.html` | **готовая страница.** Открывается двойным кликом, без сервера и без JS |

## Карточка портфеля на «Обзоре»

Четыре экрана: как сейчас · присланный макет 1в1 · рабочий вариант ·
тёмная тема и узкая колонка конструктора. Плюс таблица «поле макета →
поле кода»: что берём из `calcPf`/`calcHold`/`dayDelta`, а чего в проекте нет.

| файл | что это |
|---|---|
| `pf-card-mockups.src.html` | **исходник** |
| `pf-card-mockups.html` | **готовая страница** |

Пересборка после правки исходника — имя набора аргументом:

```sh
node dev/mockups/build-mockups.js            # trading (по умолчанию)
node dev/mockups/build-mockups.js pf-card
```

Сборщик кладёт рядом ещё `trading-mockups-artifact.html` — ту же страницу без
обёртки `<html>/<head>/<body>` для публикации. Он в `.gitignore`: генерируется
из исходника и в истории не нужен.

**Почему статика, а не живой скрипт.** Просмотрщики часто показывают HTML
снимком, не выполняя `<script>` — тогда все экраны оказываются пустыми `<div>`.
Поэтому итоговая страница не содержит ни одного скрипта.

**Ловушка при правке.** Секция «Строка терминала, крупно» рисует выноски по
координатам якорей, снятым с живой строки один раз и запечённым в массив
`anchors`. Меняешь состав шапки — открой пересобранную страницу, сними позиции
элементов заново и обнови массив, иначе линии-указатели поедут.

Решения, которые стоят за макетами, — в памяти проекта: `trading-fullscreen-plan`.
