# Подключаем Supabase — подробная инструкция простыми словами

**Что такое Supabase и зачем он нам.** Это «облачная база данных с
аккаунтами» — бесплатный сервис, где будут храниться пользователи сайта,
их пароли (в зашифрованном виде), портфели и настройки. Пока он не
подключён, сайт работает как раньше: всё хранится только в браузере
посетителя. После подключения появятся настоящие регистрация, вход
с любого устройства и админка.

**Сколько времени займёт:** минут 10–15. Аккаунт на supabase.com у вас
уже есть — остальное по шагам ниже. Испортить ничего нельзя: каждый шаг
можно повторить заново.

---

## Шаг 1. Создаём проект

Проект — это и есть ваша база данных. Один сайт = один проект.

1. Заходим на **supabase.com** и жмём **Sign in** (вход в ваш аккаунт).
2. Если сервис попросит создать **организацию** (organization) — это просто
   «папка» для проектов. Введите любое имя (например `solomina`), план
   оставьте **Free**, жмите **Create organization**.
3. Жмём зелёную кнопку **New project**.
4. Заполняем форму:
   - **Project name** — любое имя, например `madame-solomina`;
   - **Database Password** — нажмите **Generate a password** и сохраните
     его куда-нибудь (в заметки). Сайту этот пароль НЕ нужен — он
     пригодится, только если когда-нибудь полезете в базу напрямую;
   - **Region** — выберите **Frankfurt (eu-central-1)** — это ближайший
     к России дата-центр, сайт будет отвечать быстрее.
5. Жмём **Create new project** и ждём 1–2 минуты. Наверху будет крутиться
   «Setting up project…» — когда закончит, откроется главная страница
   проекта. Готово.

---

## Шаг 2. Создаём таблицы (копипаст одного файла)

Сейчас база пустая. Мы одним махом создадим в ней все таблицы и правила
доступа — они уже написаны в файле `supabase/schema.sql` в этом репозитории.

1. В меню **слева** найдите пункт **SQL Editor** (иконка с символами `>_`).
   Нажмите.
2. Нажмите **New query** (создать новый запрос) — откроется большое пустое
   поле для текста.
3. Откройте файл **`supabase/schema.sql`** из репозитория сайта, выделите
   в нём **всё** (Cmd+A) и скопируйте (Cmd+C).
4. Вставьте в поле на сайте Supabase (Cmd+V) и нажмите зелёную кнопку
   **Run** (или сочетание Cmd+Enter).
5. Внизу должна появиться надпись **«Success. No rows returned»** —
   это значит «всё выполнено, показывать нечего». Так и должно быть.

Если вылезла ошибка — ничего страшного: проверьте, что скопировали файл
целиком с первой строки, и запустите ещё раз. Скрипт устроен так, что его
можно запускать повторно сколько угодно — он ничего не сломает.

> **Обновляли сайт?** Когда в сайт добавляют новые возможности, которым нужна
> база (например, кнопка **«Удалить аккаунт»** в личном кабинете — ей нужна
> функция `delete_own_account`), просто **повторите шаги 1–5 с обновлённым
> `supabase/schema.sql`**. Повторный запуск безопасен и «донакатит» новое.

**Что мы только что создали:** табличку с профилями пользователей
(имя, роль, блокировка), табличку с их данными (портфели, настройки),
журнал событий (кто когда регистрировался и входил) и правила доступа:
каждый пользователь видит только своё, администратор — всё.

## Шаг 3. Соединяем сайт с базой (два ключа)

Сайту нужно знать адрес вашей базы и «публичный ключ» для обращения к ней.

1. В меню слева, в самом низу, нажмите **Project Settings** (шестерёнка).
2. Выберите раздел **API** (в новых версиях интерфейса — **API Keys**
   и/или **Data API**).
3. Там нужны две вещи:
   - **Project URL** — адрес вида `https://abcdefgh.supabase.co`;
   - ключ **anon public** — длиннющая строка из букв и цифр, начинается
     с `eyJ…` (в новом интерфейсе может называться **Publishable key**
     и начинаться с `sb_publishable_…` — подойдёт любой из двух).
     Рядом с ключом есть кнопка-копирование.

   ⚠️ На той же странице есть ключ **service_role** (secret) — его никуда
   не вставляем и никому не показываем. Он даёт полный доступ к базе.
   Нам нужен только **публичный** (anon/publishable) — он безопасный,
   доступ ограничивают правила из шага 2.

4. Откройте в репозитории файл **`public/js/supabase-config.js`** и
   вставьте оба значения между кавычек:

```js
window.SUPABASE_URL = 'https://abcdefgh.supabase.co';
window.SUPABASE_ANON_KEY = 'eyJhbGciOiJI…длинный-ключ…';
```

5. Сохраните файл и задеплойте сайт как обычно.

> 💡 Можно проще: пришлите мне в чат Project URL и anon-ключ — я сам
> вставлю их в файл и сделаю коммит. Публичный ключ можно спокойно
> отправлять в переписке.

## Шаг 4. Настраиваем вход и письма (2 минуты)

1. В меню слева: **Authentication** → вкладка **URL Configuration**:
   - **Site URL** — впишите адрес вашего сайта (тот, по которому его
     открывают люди). На этот адрес будут вести ссылки из писем
     «подтвердите почту» и «сброс пароля»;
   - ниже в **Redirect URLs** нажмите **Add URL** и добавьте
     `http://localhost:8787/**` — чтобы вход работал и при локальной
     разработке. 
2. **Authentication** → **Sign In / Up** (в некоторых версиях: Providers →
   **Email**). Здесь один важный переключатель — **Confirm email**
   («подтверждение почты»):
   - **Выключить** — рекомендую для старта: регистрация срабатывает сразу,
     без писем. Включите позже, когда сайт обрастёт пользователями;
   - **Оставить включённым** — тогда каждому новому пользователю придёт
     письмо со ссылкой. Учтите: встроенная почта Supabase отправляет
     всего **3–4 письма в час** (защита от спама). Для настоящей работы
     с письмами позже нужно будет подключить свой SMTP
     (Authentication → Emails → SMTP Settings) — например, бесплатный
     тариф Resend или Brevo.

Письма по умолчанию на английском. Русские тексты правятся в
**Authentication → Emails → Templates** (это можно сделать когда угодно).

---

## Шаг 5. Делаем себя администратором

1. Откройте сайт и **зарегистрируйтесь** через форму на Главной —
   как обычный пользователь (имя, email, пароль).
2. Вернитесь в Supabase → **SQL Editor** → **New query**, вставьте строку
   ниже (email уже ваш) и нажмите **Run**:

```sql
update public.profiles set role = 'admin' where email = 'clover3300@gmail.com';
```

3. Обновите страницу сайта (F5). В сайдбаре появится пункт **«Админка»**
   с иконкой щита, а в личном кабинете (аватар справа сверху) — кнопка
   «Админка».

Дальше назначать и снимать админов можно прямо из админки сайта —
SQL больше не понадобится.

---

## Шаг 6. Проверяем, что всё работает

- **Вход:** на Главной войдите со своими email/паролем → кнопка скажет
  «Готово ✓», сайт перейдёт в раздел «Расчёт».
- **Облако:** откройте личный кабинет (аватар справа сверху) — в шапке
  панели должна быть зелёная пилюля **«облако»** (раньше было «локально»).
- **Синхронизация:** создайте портфель, затем откройте сайт в другом
  браузере (или в режиме инкогнито) и войдите — портфель приедет сам
  через пару секунд.
- **Админка:** в разделе «Админка» видно вас в списке пользователей
  и события «Регистрация»/«Вход» в журнале.

## Если что-то пошло не так

| Симптом | Что проверить |
|---|---|
| Форма как будто «не видит» базу, регистрирует по-старому | Ключи вставлены в `public/js/supabase-config.js` внутри кавычек, без лишних пробелов? Сайт передеплоен? |
| «Неверный email или пароль», хотя всё верно | Включено «Confirm email», а почта не подтверждена — найдите письмо (и в спаме) или выключите Confirm email (шаг 4) |
| Письмо не приходит | Лимит встроенной почты 3–4 письма/час. Подождите час или выключите Confirm email |
| «Слишком много попыток» | Защита от перебора — подождите минуту |
| «Админка» не появилась | Выполнен ли SQL из шага 5? Точно с тем email, под которым регистрировались? Обновите страницу |
| Ошибка `Invalid API key` в консоли | Ключ скопирован не целиком (он очень длинный) — скопируйте кнопкой рядом с ключом |
| Нужно удалить пользователя насовсем | Только из Supabase: **Authentication → Users** → три точки → Delete user. Из админки сайта можно заблокировать и очистить данные |

## Полезно знать

- **Бесплатный тариф:** 500 МБ базы и до 50 000 активных пользователей
  в месяц — для старта с огромным запасом. Единственный нюанс: если
  в проект никто не заходит 7 дней, Supabase «усыпляет» его — первый
  посетитель разбудит базу за ~30 секунд. Лечится платным тарифом ($25/мес)
  или просто регулярными заходами.
- **Пароли пользователей** хранит сам Supabase в зашифрованном виде —
  ни в нашей базе, ни в коде сайта их нет, и это правильно.
- **Вход через Telegram** на сайте пока декоративный (задел) — его
  подключение к Supabase — отдельная задача, потребуется Telegram-бот.
- **Оповещения (звоночек).** Раздел «Оповещения» в админке и звоночек
  у пользователей работают на таблицах `notifications` /
  `notification_reads` — они добавлены в `supabase/schema.sql` позже
  основных. Если база создавалась раньше, выполните файл ещё раз
  целиком (он идемпотентный) или только раздел 9 «ОПОВЕЩЕНИЯ».
  Дубль оповещения в Telegram шлёт Cloudflare Worker (`POST /api/notify`) —
  ему нужны те же секреты, что и входу через Telegram (см.
  TELEGRAM_SETUP.md), и передеплой воркера: `npx wrangler deploy`.
