# Подключаем вход через Telegram — простыми словами

Это надстройка над уже подключённым Supabase (см. `SUPABASE_SETUP.md`) —
без него работать не будет. После настройки кнопка «Войти через Telegram»
на Главной заводит настоящий аккаунт (или входит в существующий), как
обычная регистрация по почте.

**Как это устроено вкратце:** Telegram подтверждает личность пользователя
подписью, которую может проверить только владелец бота (у него есть
секретный токен). Проверку делает не браузер (там секрет светить нельзя),
а маленький серверный код на Cloudflare — он же потом создаёт пользователя
в Supabase. Два секрета (токен бота и служебный ключ Supabase) хранятся
только в Cloudflare, в код и репозиторий не попадают.

**Сколько времени займёт:** минут 10.

---

## Шаг 1. Создаём бота у @BotFather

1. Откройте Telegram, найдите **@BotFather** (официальный бот, синяя галочка).
2. Отправьте `/newbot`, придумайте имя (отображается в чате) и юзернейм
   (заканчивается на `bot`, например `MadameSolominaBot`).
3. BotFather пришлёт **токен** вида `123456789:AAH...`. Это секрет —
   никому кроме нас его не показывайте, скопируйте в заметки.
4. Число **до двоеточия** в токене (в примере `123456789`) — это
   **bot_id**, он не секретный, понадобится дальше.

## Шаг 2. Привязываем бота к сайту (обязательно для кнопки в браузере)

Telegram не даст кнопке «Войти через Telegram» работать на произвольном
сайте — домен нужно явно разрешить.

1. Напишите **@BotFather** → `/setdomain`.
2. Выберите вашего бота.
3. Пришлите домен сайта **без `https://` и без слеша на конце**, например
   `madamesolomina.ru` или `madamesolomina.<ваш-поддомен>.workers.dev`.

## Шаг 3. Публичные данные бота — в файл

Откройте `public/js/telegram-config.js` и впишите:

```js
window.TELEGRAM_BOT_USERNAME = 'MadameSolominaBot'; // без @
window.TELEGRAM_BOT_ID = '123456789';                // число до двоеточия в токене
```

> 💡 Можно проще: пришлите мне юзернейм бота и bot_id — вставлю сам и
> сделаю коммит. Это не секреты, их можно спокойно писать в чат.

## Шаг 4. Секреты — в Cloudflare (не в код!)

Нужно два секрета: токен бота (из шага 1) и **service_role** ключ
Supabase — «мастер-ключ» с полным доступом к базе, который нельзя
вставлять в `supabase-config.js` (он для браузера, там только публичный
anon-ключ). Найти его: Supabase → **Project Settings → API** → ключ
**service_role** (secret) — там же, где раньше брали anon/publishable.

В терминале, в папке проекта:

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
```
Вставьте токен бота, нажмите Enter.

```bash
npx wrangler secret put SUPABASE_SERVICE_ROLE_KEY
```
Вставьте service_role ключ, нажмите Enter.

Секреты сохраняются в самом Cloudflare-проекте — их не видно ни в
репозитории, ни в коде, ни в панели без специального доступа.

## Шаг 5. Деплой

```bash
npx wrangler deploy
```

Теперь у сайта появился маленький серверный код (`worker/index.js`),
который проверяет вход через Telegram — до этого шага сайт был чисто
статическим.

## Шаг 6. Проверяем

- **В браузере:** Главная → «Войти через Telegram» → всплывающее окно
  Telegram (oauth.telegram.org) → подтвердить → сайт входит и переходит
  в «Расчёт».
- **Внутри Telegram (Mini App):** если сайт открыт как мини-приложение
  бота, вход происходит автоматически без всплывающих окон.
- **Админка:** новый пользователь появится в списке с именем из Telegram;
  email у него будет технический вида `id123456789@telegram.mstelegram.local`
  — это нормально, такой аккаунт никогда не получает писем и создан только
  для входа.

## Если что-то пошло не так

| Симптом | Что проверить |
|---|---|
| Всплывающее окно не открывается / ошибка про домен | Домен привязан через `/setdomain` **точно** тот же, с которого открыт сайт (без `https://`, без слеша) |
| «Вход через Telegram пока не настроен» | Не заполнен `public/js/telegram-config.js` (TELEGRAM_BOT_ID) или не подключён Supabase |
| «Вход через Telegram ещё не настроен на сервере» | Не заданы секреты в Cloudflare (шаг 4) или не выполнен `wrangler deploy` после `wrangler.jsonc` |
| «Не удалось подтвердить вход через Telegram» | Подпись не совпала — обычно означает, что токен бота в секрете набран с опечаткой; проверьте и пересохраните секрет (`wrangler secret put` можно выполнять повторно) |
| Всё заработало, но хочется объединить Telegram-аккаунт с уже существующим (по email) | Пока не реализовано — Telegram заводит отдельный аккаунт; объединение аккаунтов делается отдельно, если понадобится |

## Полезно знать

- В Cloudflare-проекте теперь есть не только статические файлы, но и
  один серверный обработчик (`worker/index.js`) — он трогает только
  адрес `/api/telegram-auth`, всё остальное по-прежнему отдаётся как
  обычные файлы сайта.
- `bot_id` и юзернейм бота — не секреты, их можно смело хранить в
  репозитории. Токен бота и service_role-ключ Supabase — секреты,
  им место только в `wrangler secret put`, никогда в файлах репозитория.
