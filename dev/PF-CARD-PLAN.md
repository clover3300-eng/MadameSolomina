# Новая карточка портфеля на «Обзоре» — план реализации

Макет утверждён 2026-07-21. Мокап: `dev/mockups/pf-card-mockups.html`
(исходник `pf-card-mockups.src.html`, пересборка — `node dev/mockups/build-mockups.js pf-card`).
Одиннадцать экранов, каждый с разбором «поле макета → поле кода».

**Код ещё не тронут.** Всё, что сделано, — макет: коммиты `06db00a` → `36a7827`.

Мокап **обязателен к сверке поэлементно** (правило проекта: утверждённый макет = 1в1,
отступления называть ДО, а не после). Экран 02 — эталон рабочей карточки.

---

## Что меняется по сути

Сейчас `.pf-card` — плитка фиксированной высоты 674 px с семью блоками: герой,
спарклайн с тумблером IMOEX/RGBI, кольцо распределения, три стата, мини-таблица
на 4 колонки, футер, меню. Новая карточка читается сверху вниз одной мыслью:
**сколько стоит → как менялось → из чего состоит**.

| было | стало |
|---|---|
| высота 674 px жёстко | высота свободная, растёт под содержимое |
| спарклайн 104 px, зажат рядом с суммой | герой выше: график 148 px, колонки 46% / остаток |
| кольцо «акции/облигации» 30 px в шапке списка | полоса-стек во всю ширину под KPI, доли **от полной стоимости**, включая `p.cash` |
| три стата: Вложено · Доход · Доходность | четыре KPI, разделённые хайрлайном: Вложено · Доход · Доходность · За день |
| мини-таблица 4 колонки, доли нет | 6 колонок: Актив · Кол-во · Средняя · Сейчас · Изм. · **Доля** |
| буквенные плашки тикеров | плашек нет, цвет только на знаке дохода и CTA |
| сортировка по `pnlPct` | сортировка **по доле** |
| раскрытие: 4 чипа (Название, Куплен, Цена, НКД) | раскрытие: **список лотов**, НКД строкой, деньги позиции, действия |
| дневное изменение не показано | KPI «За день» из `dayDelta()` |

Правило проекта, из которого выведена половина решений: **цвет остаётся за знаком
прибыли и за CTA**, всё остальное — на серой шкале.

## Открытые вопросы — решить ДО кода

1. **Сегмент «День» в переключателе периода.** Внутридневных данных в проекте нет:
   `chartRaw[pid].series` — по дням из «Теста», `snaps` — один снимок в день.
   Рекомендация (экран 09, вариант A): **«День» убрать**, остаются 30д / Год / Всё —
   дневная дельта уже стоит отдельным KPI. Общее правило: период, для которого нет
   данных, не показываем вовсе, а не показываем пустым (касается и «Года» у портфеля,
   которому 40 дней).
2. **Бенчмарк IMOEX/RGBI потерян.** Тумблер `.pfc-imtgl` и наложение индекса
   (`pfBench`, `chartImoex`) в новом макете не нарисованы — я убрал их, не обсудив.
   Варианты: (а) переселить сравнение с индексом в подвкладку «Портфель»;
   (б) вернуть в карточку кнопкой в углу графика; (в) в настройки виджета.
   **Нужно решение.**
3. **Оверлей «весь состав»** (`holdsOverlayHtml`, `.pfc-holdsover`) и оверлей графика
   (`pfOpenChartAssets`) в макете заменены кнопкой подвала «Все позиции ›» → подвкладка
   портфеля. Подтвердить, что оверлеи убираем, а не оставляем оба входа.
4. **Заголовки групп «Акции» / «Облигации»** (экран 06, третий вариант) — запасной
   ход, если без плашек классы активов перестанут различаться. По умолчанию НЕ берём.

## Блок 1 — каркас карточки

Эталон: **экран 02**. Только «Обзор», без раскрытия и без краевых состояний.

Файлы: `public/js/portfolios-cards.js` (`cardHtml`, строка 47), `public/css/portfolios.css`
(`.pfc-*`, ориентиры в шапке файла), `public/css/portfolios-r7.css` (оверрайды под
`#panel-portfolios`).

1. Шапка: имя · бейдж брокера · период (сегменты) · три служебные иконки (копировать,
   скрыть, шестерёнка). Переключатель периода переиспользует `segBtn()` из
   `portfolios-dash.js:2105` — не рисовать свой.
2. Герой: `--pf-hero` в две колонки **46% / остаток**. Долю, а не `auto`: иначе длинное
   число отжимает график. Кегль суммы ступенями **по числу цифр** (≤7 → 38 px,
   8–10 → 30 px, 11+ → 25 px). Считать по количеству цифр, **не по `scrollWidth`** —
   при zoom 0.9 замеры врут.
3. KPI-полоса: четыре равные колонки, разделённые хайрлайном; крайние прижаты к полям.
   Третья строка каждой ячейки — моно, табличные цифры, **везде число**:
   `21 600 ₽ свободно` · `за 131 день` · `+14,2% годовых` · `+0,76% сегодня`.
   Русское склонение дней обязательно.
4. Полоса распределения: одна краска в трёх плотностях (62 / 32 / 20 % чернил;
   тёмная тема — 72 / 38 / 24 % светлой), высота 4 px. Доли **от полной стоимости**,
   вместе с `p.cash`, иначе проценты не сходятся с суммой в герое.
5. Таблица позиций: `table-layout:fixed`, ширины `31/13/16/16/12/12 %`,
   `th+th, td+td { padding-left:14px }`. **Паддинг входит в ширину колонки** —
   менять ширины и паддинг только вместе. Имена колонок — те, что уже приняты в
   проекте: Средняя · Сейчас · Изм. (так же в `pfxPortHoldRowHtml`).
6. Доля позиции: `hc.value / c.value * 100`, формула уже есть в
   `portfolios-tabs.js:1132`. Сортировка списка — по доле.
7. Живые числа: новым узлам нужны свои `data-live`. Ключи `pfh:<hid>` — **общие** для
   мини-таблицы и любых копий той же бумаги, так сделано намеренно
   (`portfolios-cards.js:174–207`).
8. Высота: на «Обзоре» карточка растёт. Снять `height:674px` только для сетки «Обзора»;
   в блоке конструктора с заданной высотой поведение прежнее (см. блок 5).

## Блок 2 — раскрытая строка

Эталон: **экран 05**.

1. Состояние прежнее — `PF.openRows[hid]`, точечная вставка/удаление соседнего `<tr>`
   без ре-рендера (`pfToggleAssetRow`, `portfolios-cards.js:1558`). **Аккордеона нет**:
   раскрытых строк может быть сколько угодно, карточка обязана это переживать.
2. Содержимое новое: список лотов (дата · кол-во · цена · сумма) из `ensureLots(h)`,
   НКД **строкой под лотом**, справа деньги позиции (стоимость, доход ₽, годовых
   через `annualize()`, срок от `c.firstDate`), снизу действия.
   Старые четыре чипа не переносить: название и цена покупки теперь в самой строке.
3. Действия: «Докупка» → `pfAddLot`; «Открыть в терминале» → `pfOpenTicker` →
   `openStockDetail`; у облигаций вместо терминала — купоны (лента `.cpx-*`).
4. **Два клика в одной строке**: вся строка раскрывает, тикер уводит в терминал.
   Аффорданса (пунктир + метка «↗ терминал») только при наведении на сам тикер.
   У облигаций тикер некликабелен — терминала для ОФЗ нет, в подвкладке так же.

## Блок 3 — краевые состояния

Эталон: **экран 08**. Шесть штук, без них в прод нельзя.

1. **Прогрев** (`pfCardWarming`, `skelHtml`, `portfolios-core.js:372`) — самое частое
   состояние, видно при каждой загрузке. Состав, количество и **средняя цена**
   известны из localStorage сразу → рисуются настоящими; скелетоны только там, где
   ждём биржу. Карточка не должна мигать составом.
2. **Пустой портфель** — обрывается сразу после героя: KPI, полосы и таблицы нет
   вовсе. Вместо них объяснение и два входа: вручную и импорт из брокера.
3. **Всё куплено сегодня** (`pfAllBoughtToday`) — доход есть, доходность и «за день»
   прочерк: годовые от одного дня дают бессмыслицу, вчерашнего снимка нет.
4. **Нет котировки** — `curPriceInfo` молча падает на цену покупки, итог выглядит
   настоящим, но врёт. Строка гасится, «…» и прочерк вместо чисел, плашка объясняет
   неточность. **Прочерк честнее нуля**: ноль читается как «упало в ноль».
   Хелперы есть: `quoteMissing`, `noQuoteCell` (`portfolios-core.js:351`, `:361`).
5. **Брокерский read-only** — снапшот замещающий, поэтому в раскрытии не должно быть
   «Докупки» и «Продать»: созданные лоты исчезнут при следующей синхронизации.
   Плюс честная строка про позиции вне трекера (`brokerPfExtraHtml`).
6. **Скрытый** — сказать словами, что из капитала и аналитики портфель **не выпал**
   (см. память `hide-scope-overview-only`); сейчас об этом не написано нигде.

Сюда же — решение по сегменту «День» из открытых вопросов.

## Блок 4 — режим «Скрывать суммы»

Эталон: **экран 10**. Файл `public/js/sums-privacy.js` (138 строк), стили
`.sum-mask` в `public/css/profile-menu.css:463`.

Модуль маскирует только **листовой** элемент с текстом «число + ₽»
(`isMoneyLeaf` отсекает всё, у чего есть `firstElementChild`). Новая карточка ломает
это в обе стороны:

1. **Герой не размоется**: знак ₽ вынесен в `<small>`, `.pn-val` больше не лист, а в
   самом `<small>` текст без цифры. Дельта — то же самое, внутри `<u>за 30 дней</u>`.
   Это свойство разметки, а не частный случай: любая сумма с прижатым тегом выпадает.
   Лечение: **помечать деньги явным атрибутом**, который модуль уважает наравне со
   своим правилом, а не подгонять вёрстку под регулярку.
2. **Цены размывать не надо** — «Средняя», «Сейчас», цены лотов суть публичные
   котировки Мосбиржи. Модуль это уже понимает и пропускает всю вкладку «Рынок»
   (`SKIP_SEL`), но в карточке размывает те же числа. Побочно видна несогласованность:
   цена акции размывается, цена ОФЗ в процентах номинала — нет.
3. **Количество прятать надо** — сейчас открыто (нет ₽), но `qty` × публичная цена
   даёт размер позиции устным счётом.
4. Проценты остаются открытыми осознанно — они не выдают абсолютных величин.
5. Индикатор режима в шапке карточки: размытые числа сейчас неотличимы от скелетонов
   прогрева из блока 3.

## Блок 5 — виджет, тёмная тема, проверка

Эталон: **экран 07**.

1. Та же `cardHtml` рендерится блоком конструктора `pf:<id>`
   (`portfolios-dash.js:865` и `:871`) — отдельной ветки разметки нет.
   Узкий режим: KPI 2×2 (разделители только между колонками, строки разведены
   отступом), «Средняя» и «Доля» уходят, остаётся 4 колонки.
2. Правило проекта: **контент подстраивается под размер виджета** — `pfdRowsFor` +
   ResizeObserver, кнопка-действие не клипуется никогда.
3. При заданной вручную высоте (`.pfd-item.pfd-hset`) — внутренний скролл списка,
   как сейчас у `.pfc-massets`.
4. Тёмная тема — только переопределение токенов: `--pf-gn` / `--pf-rd` уже разные
   (`portfolios.css:216`). Заливка под графиком — тот же цвет с прозрачностью.
5. Проверка в превью: «Обзор» с 1, 2 и 6 портфелями; конструктор с блоком портфеля
   узким и широким; тёмная тема; включённый режим «Скрывать суммы»; свежесозданный
   пустой портфель.

## Ловушки

- **`?v=N`** у `portfolios.css` и каждого правленого js в `public/index.html` —
  иначе старый файл и у пользователей, и на свежей загрузке превью
  (кэш статики immutable через `public/_headers`).
- «Портфели» — **цепочка** файлов `portfolios-*.js`, грузится по списку в `#pfLazySrc`,
  порядок несущий; карточка в `portfolios-cards.js`, каркас рендера в `portfolios.js`.
- `softRerender` откладывает полный своп по гвардам (`PF.openMenu`, `PF.chartOpen`,
  драг/ресайз); `liveUpdate()` вызывается ДО гвардов. Раскрытые строки переживают своп,
  `scrollTop` восстанавливается по `data-skey`.
- Правка комментария в CSS легко оставляет второй `*/` — остаток файла молча отваливается.
- Новый серифный заголовок надо добавлять в общий список в `typography-tokens.css:88`.
- Превью отдаёт закешированную копию — при проверке добавлять `?v=`.
- Коммиты на русском, **не пушить**.
